> כל טענה עובדתית חייבת מקור ממוספר [1][2][3].

## הוראת הפעלה לחוקר (Perplexity Prompt)

לפני כל מחקר, שלח את ה-prompt הבא ל-Sonar Pro:

```
You are a deep technical researcher. Your task: write an exhaustive research report
about [TOOL_NAME] following EXACTLY the structure below.

CRITICAL RULES:
1. Every factual claim MUST have a numbered citation [1][2][3]
2. If you cannot find verified information for a section — write "לא אומת" 
3. Do NOT speculate or hallucinate features
4. Official sources preferred: official blog, changelog, docs, pricing page
5. For Israel-specific info: only write if you found verified Israeli user reports
   or official statements about Israel availability
6. Write entirely in Hebrew, except: button names, code, prompts, technical terms

Write the complete report for: [TOOL_NAME]
Ecosystem: [ECOSYSTEM]
Official URL: [URL]
```

## פרק 2 — תוכניות, תמחור ומגבלות

**שאלות המחקר לכל tier:**

- **מגבלות קשות (Hard Limits):**

  - requests per minute (RPM) / requests per day (RPD)
  - גודל קובץ מקסימלי להעלאה

- **מגבלות רכות (Soft Limits):**
  - מה קורה כשמגיעים לסוף? (חסימה / האטה / הודעה)

## פרק 5 — ניהול Tokens וחיסכון

**שאלות המחקר:**
- האם הכלי מציג מונה tokens בזמן אמת? איפה?
- **עלות tokens לפעולות נפוצות** (ממוצע מדווח):
  - שאלה קצרה (~50 מילים)
  - שאלה עם העלאת קובץ PDF
  - שיחה ארוכה (20+ הודעות)
- **Context Window:**
  - גודל מדויק (tokens / מילים / דפים A4 לערך)
  - מה קורה כשמתמלא: ניקוי אוטומטי / שגיאה / compression?
  - האם הכלי "שוכח" את תחילת השיחה? מתי?
- **Context Caching / Prompt Caching:**
  - האם קיים? איך מפעילים?
  - כמה חוסך?
- **טיפים לחיסכון מאומתים:**
  - אילו פיצ'רים "שורפים" tokens סתם?
  - מתי עדיף לפתוח שיחה חדשה?
  - האם "Clear context" עוזר? מה הוא עושה בדיוק?

## פרק 6 — אמנות הפרומפט לכלי הזה ספציפית

זה הפרק הכי ייחודי — כל כלי מגיב אחרת לסגנון prompt שונה.

**שאלות המחקר:**

### 6א — הקדמת "אתה מומחה..." (Role Prompting)
- האם הקדמה "אתה מומחה בX" משפרת תוצאות בכלי זה?
- האם יש מחקר/השוואה מאומתת שמראה הבדל בתוצאות?
- מה הניסוח שעובד הכי טוב: "You are an expert in..." / "Act as..." / "As a senior..." / אחר?

### 6ב — מבנה הפרומפט האופטימלי
- **סדר עדיף:** Instruction → Context → Examples → Output format?
- **אורך אופטימלי:**
  - פרומפט קצר (1-2 משפטים) vs. מפורט (1+ עמוד)
  - מתי ארוך עוזר, מתי מזיק?
- **Delimiters:** האם הכלי מגיב טוב ל: `"""`, `###`, `<tags>`, `-` bullets?
- **Chain of Thought:** האם "חשוב צעד אחר צעד" עוזר לכלי זה?

### 6ג — PDF וקבצים vs. טקסט ישיר
- **מתי עדיף להעלות PDF** ולא להדביק טקסט?
  - גודל קובץ שמכריע?
  - סוג תוכן שמכריע?
- **מתי עדיף טקסט ישיר?**
- **פורמטים מועדפים:** PDF / TXT / DOCX / Markdown — מה הכלי מבין הכי טוב?
- **מגבלות העלאה:** גודל קובץ מקסימלי / מספר קבצים / פורמטים נתמכים

### 6ד — "Magic prompts" — קודים מיוחדים
- האם יש tokens / פקודות מיוחדות שמשפרות תוצאות בכלי זה?
- לדוגמה: `/no_prose`, `TLDR:`, `Format: JSON`, `Be concise`, וכו'
- האם יש System Prompt שמומלץ להשתמש בו תמיד?

**פלט נדרש:**
```
### המבנה האופטימלי לפרומפט ב-[TOOL_NAME]:

[Role] אתה מומחה ב-[תחום]. ← כן/לא משפר — [מקור]
[Task] [תיאור המשימה בבירור]
[Context] [רקע רלוונטי]
[Format] ענה ב-[פורמט: bullets / JSON / prose]
[Length] ב-[X] מילים בערך

### מה עובד הכי טוב:
✅ [עובד] — [מקור]
✅ [עובד] — [מקור]
❌ [לא עובד / מזיק] — [מקור]

### PDF vs. טקסט ישיר:
- עד X עמודים → הדבק טקסט
- X+ עמודים → העלה PDF
- פורמט מועדף: [פורמט]

### System Prompt מומלץ לשימוש קבוע:
[פרומפט copy-paste]
```

## נספח — קריטריוני איכות לפני פרסום

לפני שמחקר נכנס ל-wiki, הוא חייב לעמוד ב:

- [ ] **מינימום 80% מהשדות מלאים** — שאר: "לא אומת"
- [ ] **כל טענה עובדתית = מקור [X]** — ללא יוצא מן הכלל
- [ ] **פרק 6 (אמנות הפרומפט) — לפחות 3 נקודות מאומתות**
- [ ] **פרק 10 (ישראל) — כתוב גם אם הכל "לא ידוע"**
